MkAgent Craft Lite 源码复用与裁剪审计

MkAgent 是 Craft Agents OSS 的 Pi-only Lite 版本，不是独立重写。此前 UI 对齐确实大规模复用了 Craft，但把许多排除功能留在代码中并仅隐藏；本轮已把它们从文件、状态、路由、协议、事件、设置和文案层物理删除。

仓库结构

保持 Craft 的 Bun monorepo 分层：三种客户端共用 WebSocket RPC、server-core 与 Pi runtime，不为 Lite 重建第二套业务架构。
层路径职责
Desktopapps/electronmain / preload / renderer、窗口和 Browser Pane
WebUI / CLIapps/webui, apps/cli共享 RPC 的浏览器和命令行入口
Serverpackages/server*会话、设置、工作区和 RPC handlers
Runtimepackages/pi-agent-server唯一 Pi Agent 子进程
Sharedpackages/core, shared, ui协议、配置、类型和 Craft UI 组件

应用/包/脚本目录：1,052 个代码文件，约 195,744 行；TypeScript 与 TSX 占主要部分。

架构

Electron Desktop ─┐ WebUI ────────────┼── typed API / WebSocket RPC ── server-core ── sessions/config/files CLI ──────────────┘ │ ▼ PiAgent only │ ▼ pi-agent-server subprocess
共享边界：renderer 不直接访问 Node；Desktop/WebUI/CLI 调用同一 handler；API key、Ollama、自定义端点全部路由到 Pi。
差异位置：Lite 改动集中在 AppShell、导航、设置、onboarding 和注册表；基础 UI、会话、附件、Browser、权限和协议尽量保持 Craft 同源。

同路径率比“相同代码率”更能回答是否重写：96.0% 文件沿用 Craft 的模块位置。逐字一致率则给出最严格下界。从 UI 对齐基线起累计变更 389 个文件，增加 6,315 行、删除 56,761 行，形态仍是明确的源码减法。

Renderer 强约束：386 个文件中，170 个必须与 Craft 归一化完全一致，211 个登记为 Lite 裁剪缝，5 个是 MkAgent 品牌资产。排除功能路径和关键调用重新出现会让 lint 失败。

保留的 Lite 能力

  • Pi API key、多上游 provider、Ollama 与自定义兼容端点。
  • 本地多工作区、会话创建/删除/归档/标记/未读、导入/导出/分支、多面板/多窗口。
  • Skills 列表、详情和 mini-agent 编辑；文件、目录、Skill mentions。
  • Plan Review、权限模式、thinking/model、annotations。
  • Browser Pane、web search/fetch、附件与 PDF/Office/代码预览。
  • Desktop/WebUI/CLI 的共享 WebSocket RPC、代理、更新、主题和 i18n。
  • Pi 会话从模型请求、session tool、工具结果回传到 renderer 展示的完整链路。
重要区分：Pi background Agent/Shell task 是运行能力，保留；Projects/Kanban/Tasks Conductor 是产品组织层，删除。
重要区分：WebUI 的远程 WebSocket transport 是共享架构，保留；remote workspace picker/binding 是产品功能，删除。

风险与待验证项

MEDIUM Lite 定制缝仍较宽

211 个 renderer 文件登记为 override。后续可逐步把精确文件从 broad prefix 中拆出，提升严格逐字复用覆盖。

MEDIUM 上游同步必须做语义审查

不能再全量复制 Craft renderer。先运行边界检查，再判断 retained capability 是否需要吸收。

LOW React Hook warnings

lint 无 error，但保留 70 个 Craft 同源 warning，适合后续独立治理。

LOW GUI 手工 smoke 尚未执行

生产构建与本地 OpenAI-compatible 端点上的真实 Pi 子进程会话已通过；发布前仍建议在全新用户目录用真实外部 provider 凭证完成 onboarding、消息、Skill、导入导出和 WebUI 重连点击链路。

商业使用与二次开发

仓库声明 Apache-2.0，通常允许商业使用、修改、再分发和闭源组合，但需保留许可证/声明并遵守专利条款。发布时仍应核对 Craft 上游和第三方依赖许可证；本报告不是法律意见。
