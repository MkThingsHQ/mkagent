## Additional bug found by actual runtime / 真实运行发现的问题

Pi 1.1 assistant messages can omit `id`. The existing subprocess forwarded anchors only when that field existed, so selecting a previous reply for a fork silently included later parent messages. The real SDK integration first failed its strict cutoff assertion. The subprocess now supplies an app correlation id when absent, forwards it on message_end, and reads the SDK leaf after append in the existing microtask. SessionManager stores that correlation id on the actual reply and persists its anchor. The same real SDK regression then passed, including a parent second turn that is absent from the branch's first API history.

A second real SDK regression exposed early Stop: after the parent reached 170 output tokens, a finished tool API added 80 and the following stream was stopped. The app previously retained 170 because forceAbort closed the foreground queue before agent_end. PiAgent now reports the adapter's known turn usage once at early queue closure and fills usage on terminal queue events that lacked it. The regression first failed (170), then passed (250). In-flight API responses without final usage are not guessed; independently running background shells and child sessions keep their existing ownership.

These fixes are adjacent to the required fork/stream accounting audit, not imports from v0.15.3.
